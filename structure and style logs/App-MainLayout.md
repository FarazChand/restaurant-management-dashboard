# app/layout.tsx

## Imports

```
import type { Metadata } from "next";  // object that allows us to configure metadata for our entire application
import { Geist, Geist_Mono } from "next/font/google"; // importing nextjs font functions
import "./globals.css";   // importing our global styles, allowing them to be applied where the html element is being configured
import { ReactNode } from "react"; // used later for typing our layout props (children aka content within body tag)
```

## Loading Fonts

```
const geistSans = Geist({         // calling Geist font function, storing return object in variable named GeistSans
  variable: "--font-geist-sans",  // the name which we use to expose the generated font to our document
  subsets: ["latin"],             // backup font
});

```

## export

```
//simple typing
type LayoutProps = {
  children: ReactNode;
};

// expecting children as props, destructuring and typing
export default function RootLayout({ children }: LayoutProps) {
  return (
    <html
      lang="en"
      className={`${geistSans.variable} ${geistMono.variable} h-full antialiased`}
    >
      <body className="min-h-full flex flex-col">{children}</body>
    </html>
  );
}
```

- since this is the "root" layout, its expected to wrap every page in the application
- in other words, all content will be wrapped in this layout
- this is why we return <html>
  - lang="en" : tells browsers, search engines, and screen readers that the primary language of the webpage is english
  - className :
    - we use our font custom property as shown, which resolves into the styles required for the fonts (requiring interpolation)
    - h-full to ensure <html> spans the entire height of the viewport - allows for designs like keeping our footer at the bottom or a full-bleed(?) background color
    - antialiased makes text characters appear slightly thinner, sharper, and cleaner. (-webkit-font-smoothing: antialiased; and -moz-osx-font-smoothing: grayscale;)
- inside the html we also return the body
  - className:
    - min-h-full allows the body to start at 100% height of its parent container, and grow to fit content that would overflow
    - flex and flex-col allow the children elements to line up vertically
- inside our body tag is where we want our content (children), aka all other pages will be rendered here

Note on heights of html and body elements:

- <html> handles height differently than the other elements, it automatically grows as it content grows - which is why we can use h-full. Content will never be clipped or cut off unless you explicitly add oveflow-hidden.
- <body> does not do this, so we need to ensure that we use min-h-full, so that its minimum is 100% of its parent but it is also still allowed to  grow if its content would overflow

### Important note on how our tailwind font utility classes are created

Chatgpt:

We import Next.js's font functions and pass them the name of the CSS custom property we want to use to expose the font. Next.js returns an object containing generated classes and other font information.

We then apply geistSans.variable to our <html> element. This applies the generated class that Next.js uses to establish the --font-geist-sans CSS custom property on the document. (similar to how we create custom css properties on our :root rule which applies them to the root aka <html>, allowing them to be accessed by any children of <html>)

--font-geist-sans is a CSS custom property whose value represents the loaded Geist font. Because it is established on <html>, it is available to descendant elements through normal CSS inheritance/cascade rules.

Our globals.css doesn't have access to the JavaScript geistSans object or the scope of layout.tsx (its just rules being applied, it doesnt have knowledge of our document). Instead, it simply references the CSS custom property by its name:

var(--font-geist-sans)

We then assign that value to Tailwind's --font-sans theme variable, effectively creating an alias that allows Tailwind's font-sans utility to use the Geist font. (in other words, we are creating tailwind utility classes for our font e.g. --font-\* to create font-\* - see the /app/globalcss.md if you are still confused.)

This process is almost exactly the same as creating tailwind color utility classes except for how the custom properties are created, which is defined above.
